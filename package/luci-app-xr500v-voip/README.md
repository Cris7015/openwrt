# XR500v telephony status for LuCI

Native LuCI status and configuration for the existing dual-FXS service.
English by default, with gettext strings and a translation template under
`po/templates/`. No custom theme/CSS. No machine translation dependency.
Menu: Services / Telephony / Status, Accounts or Configuration.
URL: `/cgi-bin/luci/admin/services/xr500v-voip`.

## Data and boundaries

- RPC object `xr500v.voip`: read methods `status`, `config_get`, `accounts_get`,
  plus separately authorized `config_apply` and `accounts_apply`.
- Fixed-path SLIC selected-channel status and PCM dual-stream counters.
  Never opens voice devices or legacy reset/loopback/probe debugfs nodes.
- Reads process liveness through procd, not a second baresip ctrl_tcp client.
- Status returns account count/mode, never raw account contents or call peers.
  Accounts returns the whitelisted editable SIP fields, never the password;
  blank password means keep, and clearing requires an explicit flag.
- A running SIP process is not a verified registration. Local accounts with
  `regint=0` are explicitly labelled as local/unregistered operation.
- Hook state is not a physical-phone presence detector. An open PCM stream is
  not proof of an established call. Counters may reset with a new stream.
- Missing data stays unknown, not a fabricated zero or healthy state.
- Browser polling10s, backend cache5s to limit debugfs/ZSI reads. No per-packet
  instrumentation or automatic actions on either phone line.
- Write ACL grants only validated apply methods, not general UCI or shell
  access. It accepts service/line enable flags, echo cancellation, mild
  denoise, and integer playback25–100%. Accounts accepts one profile per port,
  including SIP credentials. Electrical controls remain outside this interface.
- Configuration starts in read-only mode. Edit / Save & Apply asks for explicit
  confirmation, checks revision and fresh idle state, saves a0600 private
  backup, updates only whitelisted UCI fields, and invokes a fixed restart
  of telephony. No global apply of unrelated pending network settings.
- Active/unknown ports block changes. There is still a race with a new incoming
  call during apply, which the UI warns may be interrupted. No-op requests do
  not save or restart. A failed restart is reported without automatic retries.

## Development tests

`scripts/test_luci_voip_backend.py` emits a ucode harness using fixtures;
pipe it to `ucode -`. It tests actual backend logic with fs/ubus/uci mocked.
No kernel/hardware access occurs in this test.

`scripts/test_luci_voip_config.py` adds mocked write-path/guard/backup/failure
tests. `scripts/luci-voip-native-smoke.cjs PLAYWRIGHT_PATH OUTPUT_DIR` tests
the real native status/forms, edit/cancel/confirmation and mobile layout.
It intercepts changed-settings requests inside the test browser; it does not
actually save or restart telephony. `scripts/luci-voip-acl-smoke.py` verifies
read-only versus write access with a temporary scoped session, then removes it.

The package is included in the local XR500v image profile. It can be installed
independently of firmware; reload rpcd to register the backend. Do not restart
the VoIP service merely to refresh this interface.

## Accounts and dialing (0.3)

- Local: no registration; account phone1/phone2 on the chosen existing IPv4
  interface. Local keypad shortcuts are `1#` and `2#` (same-port calls blocked).
  Both ports must use the same local interface for these shortcuts.
- Provider: SIP username, domain/registrar (host or IPv4, optional port),
  optional authentication user, write-only password, optional outbound proxy,
  UDP/TCP, registration enable/interval and Baresip DTMF signaling preference.
  The domain is the AoR/registration target, proxy is a SIP next hop: there
  is no invented independent `registrar` Baresip setting.
- Create a provider VLAN/interface using standard Network pages, including
  its addressing, DNS, routes and firewall. Select it here. No VLAN IDs,
  routing rules or firewall openings are assumed or generated by this app.
- Binding restricts SIP/SDP to the selected IPv4 address; Linux routing and
  DNS still need correct provider configuration. A down/missing interface
  prevents that port from starting, with no fallback. netifd events re-render
  profiles; procd compares generated file contents, leaving unchanged ports
  running. A real address/link change can interrupt calls on that port.
- Custom accounts files remain untouched, default to legacy operation until
  explicitly opting in, and can be selected again. Nonstandard legacy
  speeddial syntax is not exposed or adopted by this editor.
- Keypad collection is pre-call only: 8 kHz s16 DTMF detector in a temporary
  child. Parent hook/ring polling remains responsive. Child is stopped and
  reaped before Baresip acquires the exclusive PCM device. No recordings.
  `#` sends, 4 s interdigit timeout, 32 digits maximum, 30 s total maximum;
  hang up to cancel/retry. Phone hardware must still be verified separately.
- Does not implement in-call analog-to-RFC4733 conversion, TLS/SRTP, automatic
  NAT traversal, an emergency dialing plan, pulse dialing or arbitrary SIP
  account syntax. A Baresip DTMF setting alone does not prove IVR compatibility.
- Libre 3.16 parses auth tokens without unquoting. Unsupported spaces,
  semicolons, quotes, backslashes, angle brackets/control bytes are rejected,
  never silently escaped into different credentials. UCI/runtime files and
  backups containing passwords are private (0600).
